## 1. プロジェクト概要

### 1.1. プロジェクト名
**Music Like**（仮称）- アイドル好き向け音楽共有SNS

### 1.2. 目的
アイドル好きが好きな音楽を共有し、自然に趣味の合う人と繋がることができるSNSプラットフォームを提供する。

### 1.3. 背景
- 既存のマッチングアプリは「出会い」が主目的で、音楽好きには敷居が高い
- 音楽共有を中心にしたSNSは、より自然で安全な繋がりを生む
- アイドルファンコミュニティは熱量が高く、音楽共有の需要が大きい

### 1.4. スコープ
**Phase 1（MVP）**: 音楽共有とソーシャル機能のコア実装
**Phase 2**: API連携、イベント機能
**Phase 3**: 収益化機能

---

## 2. コンセプト

### 2.1. コアコンセプト
**「好きな音楽を共有し、趣味が合う人と自然に繋がる音楽SNS」**

### 2.2. コンセプトの定義

```
旧コンセプト（マッチングアプリ）:
  - マッチングがメイン、音楽は手段
  - スワイプ型UI
  - 相互いいね必須

新コンセプト（音楽SNS）:
  - 音楽共有がメイン、繋がりは結果
  - フィード（タイムライン）型UI
  - フォロー自由、マッチング不要
```

### 2.3. 価値提案
- **ユーザーにとって**: 推し曲を共有し、同じ音楽好きと繋がれる安全な場所
- **アイドルファンにとって**: 同担・他担関係なく音楽を楽しめるコミュニティ
- **市場にとって**: 既存SNSと差別化された音楽特化プラットフォーム

## 4. 機能要件

### 4.1. Phase 1（MVP）機能

#### 4.1.1. 認証機能

| ID | 機能名 | 詳細 | 優先度 |
|----|--------|------|--------|
| AUTH-001 | LINE認証 | LINE Loginによるソーシャルログイン | 高 |
| AUTH-002 | Apple認証 | Apple Sign-Inによるソーシャルログイン（iOS必須） | 高 |
| AUTH-003 | Google認証 | Googleアカウントによるソーシャルログイン | 高 |
| AUTH-004 | ログアウト | セッション終了処理 | 高 |

**詳細仕様**:
- 認証ボタンは3つを同列・同サイズで垂直配置
- 初回ログイン時はプロフィール作成フローへ誘導
- セッション有効期限: 30日間
- リフレッシュトークンによる自動ログイン

#### 4.1.2. プロフィール機能

| ID | 機能名 | 詳細 | 優先度 |
|----|--------|------|--------|
| PROF-001 | プロフィール作成 | 初回登録時のプロフィール作成 | 高 |
| PROF-002 | プロフィール編集 | 登録後のプロフィール編集 | 高 |
| PROF-003 | プロフィール閲覧 | 他ユーザーのプロフィール閲覧 | 高 |
| PROF-004 | 画像アップロード | プロフィール画像の登録（1-6枚） | 高 |

**プロフィール項目**:

**基本情報**:
- ニックネーム（必須、3-20文字）
- 年齢層（選択式: 18-22, 23-27, 28-32, 33-37, 38+）
- 性別（任意: 男性/女性/その他/非公開）
- 居住地域（市区町村レベル）
- 自己紹介文（任意、最大500文字）

**アイドル情報**:
- 推しグループ（複数選択可、最大5グループ）
- 推しメンバー（グループごとに選択可）
- ファン歴（選択式: 1年未満, 1-3年, 3-5年, 5年以上）
- オタ活スタイル（複数選択）:
  - ライブ・コンサート参加
  - 握手会・チェキ会参加
  - CD/グッズ収集
  - 遠征（地方公演）
  - 配信視聴メイン
  - SNS応援活動
- 同担歓迎/拒否設定
- 現場参加頻度（月1回未満, 月1-3回, 月4回以上）

#### 4.1.3. 投稿機能

| ID | 機能名 | 詳細 | 優先度 |
|----|--------|------|--------|
| POST-001 | プレイリスト投稿 | プレイリストURL貼り付けで投稿作成 | 高 |
| POST-002 | 今聴いてる曲投稿 | 曲情報とコメントを投稿 | 高 |
| POST-003 | テキスト投稿 | テキストのみの投稿（ライブレポート等） | 高 |
| POST-004 | 投稿編集 | 自分の投稿を編集 | 中 |
| POST-005 | 投稿削除 | 自分の投稿を削除 | 高 |
| POST-006 | ハッシュタグ | #タグによる分類・検索 | 中 |

**プレイリスト投稿の仕様**:
1. ユーザーがプレイリストURL貼り付け
2. システムがOGP（Open Graph Protocol）メタデータを自動取得
3. プレビュー表示（サムネイル、タイトル、曲数）
4. キャプション入力（任意、最大500文字）
5. ハッシュタグ追加（任意）
6. 公開範囲選択（全員/フォロワーのみ）
7. 投稿実行

**対応音楽サービス**:
- Spotify
- Apple Music
- YouTube Music
- LINE MUSIC

**今聴いてる曲投稿の仕様**:
1. 曲情報入力（曲名、アーティスト名）またはURL貼り付け
2. ジャケット画像自動取得（可能な場合）
3. コメント入力（最大500文字）
4. 投稿実行

#### 4.1.4. フィード機能

| ID | 機能名 | 詳細 | 優先度 |

| FEED-001 | タイムライン表示 | フォロー中ユーザーの投稿表示 | 高 |

**フィード表示ロジック**:

- アプリ内通知（通知タブ）

#### 4.1.10. 安全機能

| ID | 機能名 | 詳細 | 優先度 |
|----|--------|------|--------|
| SAFE-001 | ユーザーブロック | 特定ユーザーをブロック | 高 |
| SAFE-002 | 通報機能 | 不適切な投稿・ユーザーを通報 | 高 |
| SAFE-003 | ブロックリスト | ブロック中ユーザーの一覧 | 中 |
| SAFE-004 | プライバシー設定 | アカウント公開/非公開設定 | 高 |
| SAFE-005 | DM受信設定 | DM受信の制限設定 | 高 |

**ブロック機能の仕様**:
- ブロックしたユーザーの投稿が非表示
- ブロックしたユーザーからのDM受信拒否
- ブロックしたユーザーは自分をフォロー不可
- ブロックは一方向（相手には通知なし）

**通報機能の仕様**:
- 通報カテゴリ:
  - 不適切な言動
  - スパム
  - なりすまし
  - ハラスメント
  - その他
- 通報理由の記述（任意）
- 運営による審査・対応

**プライバシー設定**:
- アカウント公開/非公開
- DM受信設定（全員/フォロー中/フォロワー/なし）
- プロフィール表示範囲

## 6. ユーザーストーリー

### 6.1. 新規ユーザー登録

**As a** 新規ユーザー
**I want to** LINEアカウントで簡単にログインしたい
**So that** 面倒な登録作業なしにアプリを始められる

**受入基準**:
- [ ] LINE認証ボタンをタップできる
- [ ] LINE認証画面に遷移する
- [ ] 認証成功後、プロフィール作成画面に遷移する
- [ ] 認証失敗時、エラーメッセージが表示される

### 6.2. プレイリスト投稿

**As a** アイドルファン
**I want to** 推しの曲をまとめたプレイリストを投稿したい
**So that** 同じ推しのファンと共有できる

**受入基準**:
- [ ] SpotifyのプレイリストURLを貼り付けできる
- [ ] プレイリストのサムネイル・タイトル・曲数が自動表示される
- [ ] キャプションを入力できる
- [ ] ハッシュタグを追加できる
- [ ] 投稿ボタンで投稿が完了する
- [ ] 投稿がフィードに表示される

### 6.3. フィード閲覧

**As a** ユーザー
**I want to** フォロー中のユーザーの投稿を見たい
**So that** 新しい音楽や情報を発見できる

**受入基準**:
- [ ] ホーム画面にフィードが表示される
- [ ] フォロー中ユーザーの投稿が時系列で表示される
- [ ] スクロールで追加の投稿が読み込まれる
- [ ] リフレッシュで最新投稿が取得される
- [ ] 投稿の種類（プレイリスト/今聴いてる曲/テキスト）が視覚的に区別される

### 6.4. いいね・コメント

**As a** ユーザー
**I want to** 気に入った投稿にいいねやコメントをしたい
**So that** 投稿者とコミュニケーションできる

**受入基準**:
- [ ] いいねボタンをタップできる
- [ ] いいね数が即座に更新される
- [ ] いいねを取り消せる
- [ ] コメント入力欄が表示される
- [ ] コメントを投稿できる
- [ ] 投稿者に通知が送られる

### 6.5. ユーザーフォロー

**As a** ユーザー
**I want to** 同じ推しのファンをフォローしたい
**So that** その人の投稿がフィードに表示される

**受入基準**:
- [ ] 推しグループで検索できる
- [ ] 検索結果からプロフィールを閲覧できる
- [ ] フォローボタンをタップできる
- [ ] フォロー成功時、ボタンが「フォロー中」に変わる
- [ ] 相手に通知が送られる
- [ ] フォロー中ユーザーの投稿がフィードに表示される

### 6.6. ダイレクトメッセージ

**As a** ユーザー
**I want to** もっと話したいユーザーとDMしたい
**So that** プライベートに会話できる

**受入基準**:
- [ ] プロフィールから「メッセージ」ボタンをタップできる
- [ ] DM画面に遷移する
- [ ] メッセージを入力できる
- [ ] 送信ボタンでメッセージが送信される
- [ ] 相手にリアルタイムでメッセージが届く
- [ ] 相手に通知が送られる

## 9. セキュリティ要件

### 9.1. データ保護
- **通信暗号化**: TLS 1.3
- **保存時暗号化**: AES-256（Supabaseデフォルト）
- **パスワード**: ハッシュ化（bcrypt）※メール認証時のみ
- **トークン管理**: JWT、リフレッシュトークンによる自動更新

### 9.2. 認証・認可
- **OAuth 2.0**: LINE/Apple/Google認証
- **セッション管理**: Supabase Auth
- **Row Level Security**: Supabaseの行レベルセキュリティ

### 9.3. プライバシー保護
- **最小限の情報収集**: 必要最小限の個人情報のみ
- **データ削除権**: ユーザーはいつでもアカウント削除可能
- **プライバシーポリシー**: 明示と同意取得

### 9.4. コンテンツセキュリティ
- **不適切言語フィルター**: NGワードリストによる自動検閲
- **画像検閲**: 将来的にAI画像検閲導入検討
- **通報システム**: ユーザー通報による運営審査

### 9.5. 監査ログ
- **ユーザー行動ログ**: ログイン、投稿、DM送信等
- **保持期間**: 3年間

## 12. リスクと対策

### 12.1. 技術的リスク

| リスク | 影響 | 確率 | 対策 |
|--------|------|------|------|
| Supabaseのパフォーマンス低下 | 高 | 中 | キャッシュ戦略、有料プラン移行 |
| OGP取得の失敗 | 中 | 中 | フォールバック処理、手動入力 |
| プッシュ通知の不達 | 中 | 低 | アプリ内通知併用 |

### 12.2. ビジネスリスク

| リスク | 影響 | 確率 | 対策 |
|--------|------|------|------|
| ユーザー獲得不足 | 高 | 中 | ニッチ特化マーケティング |
| 競合サービスの台頭 | 中 | 低 | コミュニティ重視、差別化 |
| 収益化の遅延 | 中 | 中 | フリーミアムモデル、広告 |

### 12.3. 運用リスク

| リスク | 影響 | 確率 | 対策 |
|--------|------|------|------|
| 不適切コンテンツの投稿 | 高 | 高 | 通報機能、運営審査 |
| ユーザー間トラブル | 中 | 中 | ブロック機能、利用規約 |
| セキュリティインシデント | 高 | 低 | セキュリティ監査、定期更新 |
